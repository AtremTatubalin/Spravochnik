# Объём, статус и правила достоверности

## Что является готовым

- Архитектура продукта и модулей.
- Структура базы и версионирования.
- Модель источников и нормативных изменений.
- Базовые физические формулы, не требующие закрытых таблиц.
- Алгоритмы валидации и представления неопределённости.
- Форматы для импорта материалов, подшипников, посадок, профилей, крепежа и резьб.
- Пакет заданий для Codex.

## Что нельзя честно считать полностью собранным

Полная нормативная база включает тысячи строк сортамента, полей допусков, исполнений крепежа, подшипников и свойств материалов. Для неё нужны официальные экземпляры стандартов и каталоги производителей. Поэтому архив разделяет данные на:

1. `official_metadata` — номер, наименование, статус, даты и официальный источник;
2. `verified_open_data` — открытые данные производителя или фундаментальные формулы;
3. `licensed_table_required` — данные, которые импортируются из законно полученного стандарта;
4. `engineering_reference` — ненормативная справочная информация с явным предупреждением;
5. `draft` — структура без утверждённых чисел.

## Неподлежащие автоматическому утверждению результаты

- расчёты грузоподъёмных приспособлений;
- расчёты крановых конструкций;
- сосуды и оборудование под давлением;
- ответственные сварные конструкции;
- усталостная прочность;
- контактная прочность зубчатых передач;
- расчёт посадок с натягом в расширенном виде;
- подбор материала для опасных производственных объектов.

Приложение может выполнять предварительный расчёт, но должно выдавать статус `requires_engineer_review`.
